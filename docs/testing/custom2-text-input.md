# custom2 中文输入与长文测试

本页是待执行的真机检查清单，不是已经通过的兼容性报告。发送端 Unicode 单元测试、协议测试及 APK 构建不能替代目标应用实测。

## 输入路径与边界

- Android IME → desktop IME bridge → KDE：需要桥接正常工作，且目标应用支持相应文本输入协议。源头修复保证按完整 Unicode code point 处理，不能证明每个窗口都会接收。
- 主 SessionActivity 在没有 desktop bridge 时只通过 evdev 发送可映射的按键，不保证任意中文、扩展汉字或 emoji 能输入。CharKeyEvent 携带完整码点不等于该 evdev 接收端具有通用 Unicode 注入能力。
- Linux 内的 Fcitx 是另一条输入路径，需要输入法包、GTK/Qt/XIM 前端和会话配置正确；中文显示还需要字体。旧桌面环境不会因为更新 APK 自动获得缺失软件包。
- 不兼容 Android IME 的窗口可改用 Fcitx，或从 Android 复制后通过系统剪贴板粘贴。剪贴板也应针对实际应用测试，不能承诺所有 X11/Electron 窗口兼容。

## 真机基本检查

先在普通文本编辑器操作，不把测试多行文本粘贴到终端，避免换行触发命令执行。

1. 分别记录 KDE 文本编辑器、GTK 应用及实际 X11/Electron 客户端的输入路径；不要把某一窗口的通过结果推及其他窗口。
2. 用 Android IME 输入中文候选词，测试确认、取消、合成中退格及关闭键盘。检查没有重复提交或误删此前文本。
3. 输入 `A中é😊𠮷`，核对每个字符；切换输入字段和窗口，确认旧候选词与排队的回车不会落入新字段。
4. 在无 bridge 的窗口，单独验证 Fcitx 输入和剪贴板粘贴；记录 Android IME 不可用这一限制，不以只成功输入 ASCII 判定中文通过。
5. 用中英混合、emoji、多行文本验证长文粘贴，核对完整内容而非仅看首尾。系统剪贴板上限为 1 MiB UTF-8；Android 自身 IPC 可能更早拒收，超限应提示分段，不应静默截断。
6. 长文本之后立即按回车或退格，检查按键没有插入文本中段；关闭键盘后，待发文本和控制键应停止。

如缺少中文组件，使用 KDE 菜单“中文支持检查与安装”检查环境。确认安装或更新后退出并重新进入桌面，再重复实际应用测试。
